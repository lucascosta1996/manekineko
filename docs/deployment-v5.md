# Deploying a V5 shared affiliate pool

V5 uses a version-2 resumable deployment journal, a read-only preflight and immutable pool accounting. Read [pool accounting](affiliate-pools.md) before selecting launch terms. Ethereum Mainnet is the production target; qualify on Sepolia first. The first 20-ticket Sepolia deployment, subscription funding, source verification and web publication are confirmed; see [addresses, receipts and qualification status](sepolia-20-ticket.md).

## Configuration and preflight

1. Export a reviewed V5 configuration from `apps/launch`, or copy `apps/contracts/round-v5.sepolia.example.json` to a private working directory. Replace zero address placeholders with the intended public owner and a separate enrollment-service EOA. Select `prizeBps`, `affiliatePoolBps` and `maxAffiliateSlots` independently. Numeric values are canonical decimal strings; 1000 bps means 10%. Prize plus pool must fit within 10000 bps. Omit V4 rates/allocation fields. Keep `activateSale=false`.
2. Set `V5_CONFIG_PATH`, `V5_PREFLIGHT_FROM`, and the chain RPC. Use `FACTORY_ADDRESS` only for an existing, verified V5 factory. The first deployment creates the factory, renderer and factory-only deployment helper. V4 factories cannot create V5 rounds.
3. Run `npm run v5:preflight:sepolia --workspace @manekineko/contracts` (or `v5:preflight:mainnet`). `V5_BROADCAST` defaults to `0`; these accounts-free networks perform read-only checks. Review bytecode, existing ownership, prior prize delivery, chain coordinator limits, transaction estimates and separate randomness funding.

`npm run launch:prepare -- --manifest /path/export.json --expected-hash TRUSTED_HASH --output /path/new-directory` verifies an offline export and produces `round-v5.json` plus `deployment-plan.json`. The trusted hash must come separately from the authenticated finalized record. An export hash is change detection, not a signature or approval to broadcast.

## Deployment and verification

Only an explicitly configured `V5_BROADCAST=1` with a deployment network submits transactions. Set an explicit `V5_JOURNAL_PATH` and retain it for every retry. The private journal and per-signer lock enforce one writer, bind the configuration hash, chain, signer, original canonical timestamp and fee ceiling, and persist exact signed transaction bytes and their hash before broadcasting. `V5_MAX_FEE_PER_GAS_WEI` defaults to 5,000,000,000 wei (5 gwei); fresh EIP-1559 estimates must fit that ceiling. Each stage checks the expected nonce, balance and prior receipts before proceeding. The `v5:deploy:sepolia` and `v5:deploy:mainnet` scripts stop at `funded-enrollment-open`. A retry reconciles the same signed hash and can rebroadcast only the identical transaction; it does not choose a new nonce or extend the original mint deadline. Confirmed stages are checked against canonical receipts. Never discard a journal or remove a lock without investigating the original process and transaction state. Older journals require manual reconciliation.

Verify the factory, helper, renderer and round against pinned Solidity 0.8.37, optimizer 200 and Cancun target. `scripts/verification-args-v5.cjs` reads the round constructor `[config, renderer]` from the V5 journal. The factory constructor takes its owner. The renderer and helper take no arguments; verify the helper's immutable factory binding. Exported runtime size checks include the helper containing the round creation code; it is close to Ethereum's size limit, so always rerun `npm run contracts:export` after Solidity changes.

For the first Sepolia factory, the accepted Etherscan record omitted the EVM target. Independent Sourcify verification provides exact creation and runtime matches with Cancun explicitly recorded; the renderer, helper and round were submitted to Etherscan with Cancun. Retain both evidence records and submit an explicit target for every future verification.

The round has immutable pool, prize and enrollment signer terms. Verify each on-chain value against the journal before publishing. The V5 renderer carries algorithm descriptions in metadata; V5 does not include the redundant V4 `RANDOMNESS_PROVIDER` and `SCORE_FORMULA` string getters.

## Admission service and release gates

Apply database migrations and configure the same dedicated signer, origin, Turnstile and trusted Vercel proxy controls described in [V4 admission operations](deployment-v4.md#configure-the-web-admission-service). For V5, use `AFFILIATE_TRUSTED_FACTORY_V5_<chainId>` and `AFFILIATE_TRUSTED_FACTORY_CODEHASH_V5_<chainId>`. Verify the factory, renderer and helper before trusting the journal's hash. Keep V3/V4 pins for historical collections.

Register the public collection as `affiliate-v5`, with its immutable `affiliate_pool_bps`, prize share and matching live deployment. Its program uses an empty `affiliate_rates_bps` array. Use the [staging registration and snapshot command](live-collection-sync.md), preview first, to store a verified initial snapshot under the finalized configuration UUID. Re-run it after actual test transactions; automatic observation is not yet running. Do not relabel a legacy demo or contract as V5. Authentication and enrollment both use EIP-712 version `3` with `poolBps`; the challenge database's versioned `commission_bps` field stores this exact pool offer for V5, never an individual payout rate.

Before Mainnet funds: exercise real Sepolia VRF fulfillment and unique winner settlement, pooled claims and withdrawal reserve checks, explorer verification, actual Vercel admission/abuse controls, signer operations, interrupted-transaction recovery, monitoring and an independent audit. Include a final mint with 100 active affiliates in gas qualification. Local tests bound that allocation below four million gas; this is not a guaranteed Mainnet fee. The launch automation page still prepares configurations only; connecting and qualifying a transaction worker remains a separate task.
