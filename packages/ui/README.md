# Tincta UI

The governing target is the [cross-app visual identity standard](../../docs/design/visual-identity.md), with [required quality gates](../../docs/design/quality-gates.md). The [adoption audit](../../docs/design/adoption-audit.md) distinguishes implementation from verified coverage. Source and build checks alone do not establish visual acceptance.

Shared, framework-independent React presentation for Web, Landing and Launch. Import `@manekineko/ui/styles.css` once from each root layout. Its `tokens.css` import is the only authored source for color, type, spacing, shape, motion and component metrics. App styles own composition and must not override shared control internals. Default controls are 40 px minimum with 9/14 px button padding, 14/20 px text and a 3 px radius; `any-pointer: coarse` changes the minimum to 44 px, button padding to 11/14 px and field text to 16/20 px. Dimensions use rem and grow with user text settings.

## Actions and fields

- `button`: `Button`, `LinkButton`, `IconButton`, `TextAction`, `Spinner`. Buttons default to `type="button"`; submissions specify `type="submit"`. Variants are `primary`, `secondary`, `ghost`, `destructive`. `IconButton` requires an `aria-label`; icons stay decorative. `LinkButton` renders an anchor. `TextAction` is a transparent, underlined button with a 32 px minimum target, or 44 px on coarse input. Its `inline` mode participates in sentence flow.
- `button-styles`: server-safe `buttonClassName({variant, className, fullWidth})` and `textActionClassName({inline, className})` for framework links. Do not call helpers imported from the client `button` module in a Server Component.
- Button `busy` sets `aria-busy`/`aria-disabled`, preserves keyboard focus and rejects activation while busy. `icon` reserves an 18 px slot; `busyLabel` uses that slot for a spinner. Pass all varying labels through `reserveLabels` so the grid measures their largest width. The owner still guards duplicate asynchronous operations at the request boundary and supplies meaningful completion/error status.
- `forms`: `Input`, `Textarea`, `Field`, `Checkbox`, `Radio`, `Switch`. `Field` renders a visible label and helper/error text and supplies `id`, `aria-describedby`, `aria-invalid` and `required` to its render function. Native input types retain semantic validation and keyboard editing. Use `noValidate` only with an actual accessible client validation path, plus server validation.
- Existing semantic controls may use the same explicit contracts: `ui-input`, `ui-textarea`, `ui-checkbox`, `ui-radio`, `ui-switch`, `ui-check-field`, `ui-card-action`, `ui-tab`, `ui-segment`. A card action is a semantic button with no nested interactive descendants. Selection uses `aria-pressed`, `aria-selected` or `aria-current` as appropriate. Checkbox/radio indicators are 18 px inside a clickable label target of 40/44 px.

- `icons`: Lucide React, 18 px and 1.6 stroke by default; `size="footer"` (or `16`) uses the explicit 16 px footer role. Use `Icon` with a semantic name. Decorative icons are hidden from assistive technology; put accessible names on icon-only buttons. Keep brand artwork and mathematical text unchanged.
- `select`: Radix Select. Existing option declarations and string values are accepted, with an `onChange({target:{value}})` value adapter. This is not a synthetic DOM event. The visible control is a listbox, with portaled positioning, scrolling, typeahead, disabled items, Escape and focus restoration. Radix retains a hidden form control; empty values stay empty for required validation. Label using a containing label, `htmlFor`/`id`, or `aria-label`.
- `dialog`: existing Radix Dialog exports remain available. Modal focus is contained and restored on dismissal. Use the shared `ui-dialog-*` contracts and a named close control.
- `confirm`: wrap the owning app in `ConfirmProvider` and call `await useConfirm()(options)` inside its components. Options accept `title`, `description`, `confirmLabel`, `cancelLabel`, `destructive`; a string becomes the description. Cancellation, Escape, outside dismissal and provider unmount resolve `false`; an overlapping request resolves `false`. Initial focus goes to Cancel; focus returns to the initiating element if it still exists. The promise only confirms intent: existing permissions, action validation and pending guards remain at the caller.
- `components`: `Modal` (including `drawer` and 640 px large variants), `Menu`, `Tooltip`, `Tabs`, `Disclosure`, `Card`, `Badge`, `Feedback`, `Skeleton`. Simple dialogs max at 440 px; every overlay preserves at least 16 px viewport inset and scrolls internally. Menu/tooltip placement is recalculated on scroll/resize and kept in the owner's DOM/focus scope. Menu supports arrows/Home/End/Escape and skips disabled entries. Tooltip is available on focus/hover, stays hoverable and dismisses with Escape. Tabs use automatic arrow-key activation. Disclosure uses semantic `details`/`summary`. Feedback errors remain in normal flow; callers choose appropriate live announcement semantics.
- `links` / `footer`: configured destinations only. Web app/docs and Landing website use their own relative paths. Cross-app links and contact/Telegram/X use environment configuration; missing values are visibly unavailable. Support is a coming-soon panel with no submission backend. `PublicFooter` owns the only copyright row; `legal` adds exact supplemental copy, `actions` adds quiet controls, and `brand` supplies the generated wordmark. `year` supports deterministic fixtures. Public columns are 1/2/4 at <600/600–959/960+ px. Operator shells use `ui-operator-footer` without marketing columns.

## Verification specimens

`specimens` exports `UISpecimens`, a local-only component explorer that imports the production components above. It covers type roles, every action variant, selected/disabled/busy states, field validation, semantic picker triggers, choices, select portals, menu, tooltip, tabs, dialog/drawer/confirmation, disclosure, cards, table, status, feedback, skeleton/spinner, header and footer. Specimen actions never write outside their React state. The fixture apps and browser tests live under `tests/visual`; the public applications do not mount this component.

Browser contracts are in `tests/visual/components.spec.ts`. They measure control/icon/footer geometry, coarse-input metrics at desktop width, portal type, validation, focus, modal cancellation, menus/tabs, reduced motion, forced colors and enlarged text. They also produce strict screenshot comparisons in the repository's pinned environment. A desktop `hasTouch` fixture checks the `any-pointer` branch; actual hybrid hardware, screen-reader journeys and device keyboards remain separate acceptance checks. Native OS date/color/file pickers, autofill and browser chrome are outside the app-owned trigger styling boundary.

WalletConnect AppKit uses its supported light/black theme, common font and 1 px master radius (SDK tokens multiply this into several radii). Its shadow UI, vendor wallet logos and icon set cannot be replaced by the app's CSS or Lucide wrapper through the public theme API. External wallet screens are also outside this system. Do not claim every SDK control has exactly 3 px corners.

References: [Radix Select](https://www.radix-ui.com/primitives/docs/components/select), [Lucide React](https://lucide.dev/guide/react). Dependencies are pinned in this package and the workspace lockfile.
